Auth system:
  - Services/Auth/AuthService.cs (IAuthService) - login validates bcrypt hash, enforces
    single active session (checks ActiveSessionId + ActiveSessionIssuedAt vs configured
    expiry window before allowing a new login), issues JWT with claims: sub/name, role,
    "sid" (session guid), jti. Logout clears ActiveSessionId only if the caller's sid
    still matches (defensive).
  - Controllers/AuthController.cs: POST /api/auth/login (AllowAnonymous), POST
    /api/auth/logout (Authorize), GET /api/auth/me (Authorize)
  - Middleware/SessionValidationMiddleware.cs: runs after UseAuthentication(), on every
    authenticated request re-checks the token's "sid" claim against the user's CURRENT
    ActiveSessionId in the DB. If they don't match (i.e. logged out, or another device
    logged in and this session was superseded) -> 401. This is what makes logout / device
    switching actually invalidate old tokens immediately instead of waiting for JWT expiry.
  - appsettings.json: added "Jwt" section (Key/Issuer/Audience/AccessTokenExpiryHours=12)
    and "SeedUsers" section (SalesTeamPassword/PurchasingPassword - PLAINTEXT ONLY used
    once at first startup to bcrypt-hash and seed the two accounts; never read again after
    the Users table is non-empty; never compared as plaintext anywhere in login logic).
  - Program.cs: seeds the 2 users on first run (only if Users table empty), same pattern
    as existing Products seeding.

Real-time notifications:
  - Hubs/NotificationHub.cs: [Authorize] SignalR hub. On connect, adds the connection to
    a group named after the user's role claim ("purchasing" or "quotation").
  - Program.cs: JWT bearer config has an OnMessageReceived handler that reads the token
    from the `access_token` query string specifically for requests under /hubs (browsers
    can't set custom headers on WebSocket upgrade requests, so SignalR's JS client sends
    the token via query string instead).
  - Hub mapped at: /hubs/notifications

Quotation feature:
  - Services/Quotations/QuotationService.cs (IQuotationService):
      CreateQuotationAsync - validates ClientId + all ProductIds exist, builds
        QuotationNumber as QTN-{year}-{seq:0000} (matches existing "QTN-2026-0001"
        format), computes MaterialsTotal/LaborTotal/GrandTotal.
      GetQuotationsAsync / GetQuotationAsync
      SendToPurchasingAsync(quotationId) - guards against double-send and empty
        material list, builds a CreatePurchaseRequestDto from the quotation's client +
        material items, calls IPurchaseRequestService.CreatePurchaseRequestAsync(dto,
        source:"Quotation", quotationId), links PurchaseRequestId back onto the
        Quotation, sets Status=Sent, then broadcasts SignalR event "NewPurchaseRequest"
        to the "purchasing" group with {Id, PRNumber, ClientName, ItemCount, Source,
        QuotationNumber}.
  - Controllers/QuotationController.cs - [Authorize(Roles="quotation")] on the whole
    controller. GET /api/quotations, GET /api/quotations/{id}, POST /api/quotations,
    POST /api/quotations/{id}/send-to-purchasing
  - Controllers/ClientController.cs - [Authorize(Roles="quotation")]. GET /api/clients,
    POST /api/clients (for adding a new client inline from the Quotation UI).
  - IPurchaseRequestService.CreatePurchaseRequestAsync gained optional params
    `string source = "Manual"` and `int? quotationId = null` (backward compatible -
    existing PurchaseRequestController call site untouched, defaults to "Manual").

Authorization added to existing controllers:
  - ProductsController: [Authorize] (any authenticated user - both apps need it)
  - PurchaseRequestController: [Authorize(Roles="purchasing")]
  - PurchaseOrderController: [Authorize(Roles="purchasing")]
