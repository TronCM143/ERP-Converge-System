SYSTEM DESCRIPTION

Converge is an ERP and business operations system with four main user roles:

quotation
Manages clients, CRM opportunities, quotations, products,
and invoices.

engineer
Reviews and decides quotation approval requests,
subject to configured approval limits.

purchasing
Manages purchase requests, bills of materials,
purchase orders, and suppliers.

admin
Manages users, system settings, integrations,
notifications, and all major system functions.

MAIN BUSINESS FLOW

Client and CRM Pipeline:

Leads
-> Quote
-> Proposal
-> Pending
-> Won

A separate Lost stage records unsuccessful opportunities.

Users can drag CRM cards between pipeline stages. Moving to Proposal may require
engineer or administrator approval when the quotation exceeds the configured
approval threshold.

Moving an opportunity to Won can approve the latest sent quotation, record
sales revenue, send notifications, and log the deal to a spreadsheet.

Moving an opportunity to Lost can reject the latest sent quotation and update
sales reporting.

QUOTATION FLOW

A user creates a quotation for a client using products from the catalog.

Quotation features include:

Draft, sent, approved, and rejected statuses.
Automatic quotation numbering.
Product and material line snapshots.
Validity dates.
PDF generation.
AI-assisted quotation generation.
Approval routing.
Sending a quotation to purchasing.
Quotation approval is separate from the commercial quotation status. An
engineer approving a quotation does not automatically mean that the client has
accepted it or that revenue has been recorded.

APPROVAL FLOW

A quotation exceeds the configured approval threshold.
The CRM or quotation workflow submits it for approval.
Engineers or administrators receive the request.
The request can be approved or rejected.
Rejections require a reason.
Approval limits determine whether an engineer or administrator can approve.
Notifications may be sent by email or SMS.
Stale pending requests can be escalated by a background worker.
PURCHASING FLOW

Quotation
-> Purchase Request
-> Bill of Materials
-> Purchase Order

A quotation can be sent to purchasing when it exists, has material items, and
has not already been linked to a purchase request.

Material items are transferred into purchasing. Pricing and tax information
can be taken from the originating quotation. Labor items do not participate in
the material purchasing bridge.

INTEGRATIONS

The backend supports:

PostgreSQL for persistent data.
Redis for distributed caching, with in-memory caching as a fallback.
JWT authentication.
Google OAuth for Gmail access.
Gmail, Resend, or SMTP email delivery.
SMS notifications through the configured SMS provider.
Google Sheets logging for won deals.
SignalR for real-time notifications.
Groq for AI-assisted quotation generation.
Google services for product image search.
Odoo for read-only historical sales information.
TECHNICAL ARCHITECTURE

The system uses a single repository containing two applications:

Frontend:
React + TypeScript + Vite + Tailwind CSS

Backend:
ASP.NET Core + Entity Framework Core + PostgreSQL

The frontend communicates with the backend through REST API endpoints. SignalR
is used for real-time notification events. The backend contains the main
business rules, authorization, data persistence, integrations, background
workers, and workflow enforcement.
